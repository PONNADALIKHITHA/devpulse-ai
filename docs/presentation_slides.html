DevPulse AI — Code Explainer & Debugging Tutor

Grand AI & NLP Projects | Practical Implementation

An intelligent pedagogical code explanation and debugging assistant that guides programming students through progressive Socratic hints, pinpoint root-cause analysis, and visual unified diffs.

🎯 Core Purpose

Transforming cryptic compiler stack traces into constructive, conceptual learning moments.

🚀 Target Users

First/second-year programming students, CS undergraduates, and self-taught developers.

The Problem & User Scenarios

⚠️ The Educational Challenge

  • Cryptic Compiler Errors: Beginners copy errors without understanding the root cause.
  • Passive Copy-Pasting: Generic AI chatbots supply full solutions directly, stopping students from learning.
  • Fragile Knowledge: High recurrence rate of fundamental off-by-one and null pointer errors.

💡 3 Key User Scenarios

  • Scenario A (Syntax & Runtime): A student gets an IndexError and needs to see why range(len + 1) exceeds bounds.
  • Scenario B (Socratic Tutoring): A learner uses Hint-First mode to deduce a missing recursive base condition.
  • Scenario C (Defensive Testing): A student generates boundary test cases to stress-test their implementation.
Slide 3 of 8

Core Solution & Key Features

1. Plain-English Summary

Summarizes the student's code intent in clear, accessible language before discussing errors.

2. Theoretical Root Cause

Pinpoints the computational mechanism behind the failure (e.g. 0-indexing, stack overflow).

3. Minimal Fix Philosophy

Prescribes the smallest surgical modification rather than rewriting the user's entire logic.

4. Progressive Socratic Hints

3-tiered reveal (Observation → Clue → Guidance) preventing answer-spoiling.

5. Visual Unified Diff

High-contrast additions and removals with line-by-line reasoning.

6. Edge Case & Complexity Analysis

Synthesizes boundary unit tests and compares Big-O time and space complexity.

System Architecture & Data Flow

DevPulse AI adheres strictly to the decoupled architecture required by Section 4 of the GMRIT Handbook:

[ User Browser ]
    │ HTTP / WebSocket
    ▼
[ Streamlit Frontend: app.py, pages/ ] (Input widgets, state, zero model prompts)
    │ Validation gate
    ▼
[ backend.utils.validators ] (3-15k char limits, language whitelist, sanitization)
    │ Validated dictionary
    ▼
[ backend.core.pipeline ] (Structured JSON schemas, difflib diff generation)
    │ Dual Engine Dispatch
    ├──► [ Local Static AST Engine ] (100% Offline, <40ms, zero-key reliability)
    └──► [ Neural LLM Service ] (Google Gemini 1.5/2.0 Flash / Groq LLaMA 3.3)

Technical Decisions & Tradeoffs

Design Choice Alternative Considered Engineering Justification
Streamlit Community Cloud Deployment Separate FastAPI + React Server Single repository deployable with 1-click; avoids managing dual servers.
Dual Engine (AST + Neural) Online-only API calls Guarantees zero viva/demo failure if internet drops or API quota is hit.
No Remote Execution Server-side sandbox execution Prevents server compromise; safe for multi-tenant educational hosting.
Decoupled REST Calls Heavy third-party SDKs Avoids dependency deprecation and pin conflicts during grading.

Limitations & Future Roadmap

⚠️ Known Limitations

  • Static Analysis Boundary: Cannot simulate live network I/O or multi-threaded timing races.
  • Single-File Scope: Complex multi-module projects require snippet-by-snippet input.
  • API Rate Limits: Free-tier LLMs throttle on burst traffic (handled by offline engine).

🚀 Future Roadmap

  • Client-Side WebAssembly: Integrate Pyodide for safe browser-only code execution.
  • AST Semantic Linting: Pre-compile abstract syntax trees for C++, Java, and Go.
  • Instructor Dashboard: Aggregate common student misunderstandings across a class.
